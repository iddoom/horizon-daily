## [采用顺序免疫策略的新型 HIV 疫苗进入一期临床试验](https://www.lji.org/news-events/news/post/new-hiv-vaccine-shows-unprecedented-success-in-preclinical-study/) ⭐️ 8.0/10

由拉霍亚免疫学研究所（LJI）研究人员开发的一种新型 HIV 疫苗候选物采用了前所未有的顺序免疫策略，通过注射一系列略有不同的疫苗，像课程一样逐步引导 B 细胞发育。在恒河猴的临床前试验中，该疫苗在约 44%的动物中成功产生了预期的免疫反应，目前一期人体试验已经启动。 这代表了疫苗设计中潜在的突破性范式转变，因为传统的疫苗方法由于 HIV 极高的突变率而屡遭失败。如果在人体中取得成功，这种靶向胚系的顺序免疫策略不仅可能产生首个有效的 HIV 疫苗，还可能彻底改变针对其他快速突变病原体的疫苗设计方式。 该疫苗在恒河猴中的成功率为 44%，这意味着大多数动物并未产生预期的免疫反应，而且从历史上看，大多数 HIV 疫苗候选物即使通过了一期试验也最终失败了。相关同行评议研究已发表在《Nature》上，C&EN 的独立报道也提供了超越机构新闻稿的额外背景信息。

hackernews · codebyaditya · 7月28日 13:12 · [社区讨论](https://news.ycombinator.com/item?id=49083314)

**背景**: HIV 疫苗的研发一直异常困难，因为该病毒突变速度极快，免疫系统无法跟上，且其表面蛋白被大量糖分子屏蔽。顺序免疫是一种新型策略，按特定顺序注射一系列不同的疫苗，每种疫苗靶向 B 细胞发育的不同阶段，从而逐步训练免疫系统产生能够识别多种 HIV 毒株的广谱中和抗体（bNAbs）。一期临床试验是在人体受试者中测试新药或疫苗的第一阶段，主要关注在一小群健康志愿者中评估安全性和副作用。

## [美国最大电网可能对数据中心实施临时断电以防大面积停电](https://techcrunch.com/2026/07/28/data-centers-may-face-temporary-power-cuts-to-prevent-blackouts-on-largest-us-grid/) ⭐️ 8.0/10

PJM Interconnection 是服务美国 13 个州及华盛顿特区、覆盖 6700 万人口的最大的电网运营商，目前正考虑对数据中心实施临时断电措施，因为预计电力需求将达到约 166,147 兆瓦的历史新高。这项紧急措施的背景是，主要由 AI 工作负载驱动的数据中心建设速度过快，在极端高温天气下可能使电网容量不堪重负。 这暴露了一个关键的基础设施瓶颈：AI 驱动的数据中心扩张速度已超过发电能力的增长，迫使电网运营商采取对这类高可用性设施而言 previously 不可想象的极端措施。这一决定可能为全球范围内如何管理高耗电的 AI 基础设施树立先例，可能影响云服务提供商、AI 模型训练进度以及整个科技行业的增长轨迹。 PJM 预计电力需求将超过目前 165,563 兆瓦的夏季纪录，而数据中心在美国全国电力消费中的占比预计将从 2023 年的 4%上升到 2028 年的 7-12%。电网运营商已获得紧急授权，专门削减数据中心的用电，原因是这些设施需求集中且增长迅速。

rss · TechCrunch · 7月28日 15:42

**背景**: PJM Interconnection 成立于 1927 年，最初是服务宾夕法尼亚州和新泽西州三家公用事业公司的电力联营体，后来扩展为宾夕法尼亚-新泽西-马里兰互联电网。它现在是东部互联电网的一部分，运营着全球最大的电力批发市场。AI 和机器学习工作负载的快速普及极大地加速了数据中心建设，这些设施需要为计算运行和冷却系统提供巨大且持续的电力供应。这种需求的激增发生在传统发电基础设施扩张滞后的时期，造成了供需之间的结构性失衡。

## [uv 0.12.0 发布：新项目默认采用打包构建系统](https://github.com/astral-sh/uv/releases/tag/0.12.0) ⭐️ 7.0/10

Astral 发布了 uv 0.12.0 版本，该版本使得通过 `uv init` 创建的项目默认使用原生的 `uv_build` 后端进行打包。此次更新还包含多项旨在提升安全性和规范兼容性的破坏性变更，例如拒绝不受支持的源码分发压缩格式，以及拦截可能恶意替换 Python 解释器的 wheel 文件。 此版本为新的 Python 用户开箱即用地确立了最佳实践的项目布局，确保项目能够立即被导入、安装和执行。更严格的安全规则也大幅降低了在处理来自包索引的不可信包时的攻击面。 现有的项目不受默认打包变更的影响，用户依然可以使用 `uv init --no-package` 来创建非打包布局。新的压缩格式限制无法选择停用；依赖 `.tar.bz2` 等旧格式的用户必须将其源码分发包重新构建为 `.tar.gz` 格式。

github · astral-automations-bot[bot] · 7月28日 18:58

**背景**: uv 是一款由 Astral 使用 Rust 编写的极速 Python 包和项目管理器，能够替代 pip、pipx 和 poetry 等工具。构建后端（build backend）是一种将项目源代码转换为可分发包（如 wheel）的工具，而 uv 提供了名为 `uv_build` 的原生构建后端，以实现紧密集成并提升性能。在此版本之前，`uv init` 会创建简单的、非打包的项目，这常常让后续需要手动配置构建系统以使代码能在测试中被导入的用户感到困惑。
